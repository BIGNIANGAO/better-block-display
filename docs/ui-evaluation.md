# 格挡预估视觉评估

评估及落实日期：2026-10-07。范围为界面与阅读体验，计算规则保持原有范围。简洁界面已纳入发布版 1.0.1。

## 结论

根据用户追加要求，1.0.5 直接替换原版护盾数字的显示值，固定显示预计回合末总格挡。取消额外小图标、外置数字与「显示总量」开关。原版护盾的纹理、位置、数字字体及现有动画继续由游戏绘制；当前实际格挡为零时补齐护盾的显示条件与透明度，让预测的正数正常显示。实际格挡字段不变。出牌队列、结束回合、敌方行动、预览不可用或模组关闭时恢复原版实际值。

只保留一个原版护盾数字，当前值与变化量放在悬浮提示中。1.0.7 起，预计值为零时按「始终显示」选项决定是否显示护盾、数字及悬浮提示；当前格挡大于零或部分预估提示不再强制显示零值。隐藏时仍保留预计值，避免误退回当前格挡显示。

原 docs/ui/assets/block-preview.svg 与 PNG 留作历史素材，当前渲染不再加载或绘制。原先三布局与护盾左侧水平布局均为先前方案，当前选择以本节为准。

1.0.8 起，点击结束回合后保留预计值到玩家回合末结算完成，抑制重复的护盾增益动画。敌方行动前恢复实际值，避免显示 12 后回退到 10 再增加到 12；实际受击扣格挡及非结算期动画仍由本体处理。结算期间关闭预估悬浮提示，开启新回合或关闭模组时清除暂存。

复用本体提示框纹理与字体。护盾显示总量，例如 19；悬浮显示当前值、预计值及变化量。部分预估使用 ≈，仅在悬浮提示中显示。

## 改动前核查

| 观察 | 依据 | 设计影响 |
| --- | --- | --- |
| 本体护盾位于血条左侧，图标尺寸为 64 × Settings.scale | 本体 AbstractCreature.renderBlockIconAndValue | 再复制相似护盾容易把预估与当前格挡混淆 |
| 能力图标位于血条下方，数量标签在更下方 | 本体 AbstractCreature.renderPowerIcons | 血条正下方并不是空白区 |
| healthHb 高度为 72 × Settings.scale，悬停会显示能力提示 | 本体 AbstractPlayer.refreshHitbox 与 renderPlayerBattleUi | 预估的交互区应在 healthHb 外，避免抢占本体提示 |
| 当前预估以 healthHb 左侧 -54、中心下方 -27 为锚点 | PreviewRenderer.render | 数字和本体 UI 联系较弱，固定大小交互区也没有根据文字测量 |
| 准确时颜色依赖 delta；不准确时整串数字为金色 | PreviewRenderer.render | 总量模式红色 19 容易被理解为扣血或损失 19，部分标记也混淆增减语义 |
| tooltip 使用固定偏移；renderGenericTip 本身没有屏幕边界修正 | PreviewRenderer 与本体 TipHelper | 长提示或自定义角色位置可能导致框体越界 |
| TipHelper 每帧优先接收第一个提示请求 | 本体 TipHelper.renderGenericTip 与 queuePowerTips | 不能为了预估强制覆盖卡牌或能力提示；应先避免交互区重叠 |
| 不论是否准确，末尾都会显示 ~ 的解释 | PreviewRenderer.render | 常规提示可减少一段说明 |
| 原因字符串可能含英文类名和技术术语 | GameSnapshot.add | 玩家详情应只显示本地化原因，完整技术信息保留在日志 |

最初的 smoke 截图没有可见本体血条和护盾，只能证明数字及提示渲染。本轮已补齐真实本体血条、护盾、能力图标的静止 UI 状态并重新截图。新版截图来自游戏内隔离场景，仍不等于完整对局；探索布局示意也不是游戏截图。

## 最初的三种布局

| 方案 | 常驻内容 | 优点 | 代价 | 建议 |
| --- | --- | --- | --- | --- |
| 血条右侧注记 | 小图标 + 外置数字 | 与当前格挡分开；不侵入下方能力行；没有常驻说明文字 | 需要验证图标识别与数字宽度；右侧空间不足时退到左侧安全区 | 最初选择，后改为本体护盾左侧 |
| 左侧小护盾 | 当前护盾下方再加预估护盾 | 横向空间少 | 两个护盾容易混淆，还需要额外文字区分 | 不采用 |
| 血条下方摘要 | 回合末 13 → 19 | 同时知道当前与最终值 | 文字多、重复当前格挡、占用能力行附近空间 | 不采用 |

示意里的状态控制包括增加、减少、999 上限、总量和部分预估，用于比较阅读效果；没有冒充新的计算结果或真实对局验证。当前采用的护盾左侧水平布局不同于最初的「当前护盾下方」草案。

## 推荐细节

常驻数字采用本体 blockInfoFont 及原生护盾渲染，显示总量。变化量在悬浮提示中保留正负号。≈ 只在悬浮提示的「部分预估」说明前显示，并保留原因。

提示框标题保留「回合末格挡」。一行显示「13 → 19（+6）」，然后只列来源。准确时不重复解释；不准确时加一条简短中文原因。模型仍需保留原始原因，展示层按原因类型生成玩家能理解的中英文文本，不通过删类名的字符串替换猜语义。

来源行保留计算器给出的实际变化和顺序，不启用阶段合并。例如 997 获得 6 时只显示实际 +2，不重新计算原始获得量。最多显示六条来源，超出时提示剩余数量；框体过高时继续减少显示条数。未来若合并，须以明确阶段标识为依据，不从本地化字符串拆解「冰霜 / 镀金缆线」来伪造新贡献来源。

悬停交互区覆盖原版护盾，使用角色实际 hb 与只读血条动画偏移跟随显示。只有鼠标在护盾区域且预览有效时让位于预估提示；血条其他区域与能力提示保留原生行为。提示框向上避开护盾及血条，测量高度并限制到安全边距内，来源多时提示剩余数量，原因去重后最多列两条。

数字变化不做常驻脉冲、发光或弹跳。现有行动队列期间立即隐藏的规则保留，避免用淡出展示已经失效的预测。仅在实机验证之后再考虑轻微、短时的变化反馈。

## 本轮落实

1. 图标与外置数字、根据实际字体测量的交互区、右侧不足时的左侧布局。
2. 精简提示、已知原因本地化、屏幕边界与异常长来源处理。
3. 本体血条、护盾、能力图标可见的隔离游戏截图，正负变化、总量、部分预估与上限检查。
4. 发布版 1.0.1 的 Java 8 打包和校验。没有新增设置、常驻动画或阶段合并。

## 验证范围

- 1280 × 720、1920 × 1080、2560 × 1440，以及超宽比例。
- 当前格挡 0 / 13 / 997 / 999，正变化、负变化、零变化及部分预估。
- 两种显示模式，中文、繁体中文、英文和长第三方来源名。
- 少量/大量能力，血条位置改变，画面边缘和较低血条位置。
- 鼠标在预估、原有格挡、能力、手牌区域之间移动；原有提示保持正常。
- 拖牌、出牌队列、结束回合和敌方行动时不会留下旧数字或旧提示。

本轮完成简中/繁中 720p、英文 1080p 的隔离场景验证，每次 70 项运行/渲染断言。1440p、超宽屏、任意角色、大量能力和完整对局尚未完成视觉回归；完整记录见 docs/verification.md。
